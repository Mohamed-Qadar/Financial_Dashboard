# Database Design — Somali ERP

Status: Draft v0.1 (Phase 0). This is the target relational design for the MVP. Tables are
created phase by phase through Django migrations; this document is updated when they are.

## 1. Conventions

| Rule | Detail |
|---|---|
| Primary keys | `id UUID` (generated by the application). Avoids guessable IDs in URLs and makes imports/merges safer. |
| Tenant column | Every tenant-owned table has `tenant_id UUID NOT NULL REFERENCES tenants(id)`, **including line tables**, so RLS policies are a simple column check. |
| Company column | Company-scoped tables also carry `company_id`. |
| Tenant-consistent FKs | Parents expose `UNIQUE (tenant_id, id)`; children reference `(tenant_id, parent_id)` with a composite FK (added via migration SQL), so a row can never point at another tenant's row. PostgreSQL FK checks bypass RLS, so this matters. |
| Timestamps | `created_at`, `updated_at` as `timestamptz` (UTC). `created_by_id`, `updated_by_id` → `users`. |
| Money | `NUMERIC(18,2)` amounts, `NUMERIC(18,4)` unit prices/costs/quantities, `NUMERIC(20,8)` exchange rates. Never `float`/`double`. |
| Currency | `CHAR(3)` code referencing `currencies(code)` beside every amount set. |
| Status | Short text with `CHECK (status IN (...))`. |
| Deletion | Master data is archived (`is_active = false`), not deleted. Drafts may be deleted. Posted documents are never deleted. |
| Names | Table names plural snake_case. Django apps map to table prefixes only where needed. |

Legend below: **PK** primary key, **FK** foreign key, **UQ** unique, **CK** check, **T** tenant-owned (RLS applies).

## 4. Master data

`code` char(3) PK, `name`, `symbol`, `minor_units` smallint CK 0–4. Seeded with `USD`, `SOS`
(and others on request, see open decisions on Somaliland shilling).

### company_currencies (T)
`company_id`, `currency_code`, `is_enabled`. Which currencies a company transacts in.

## 5. Inventory

Stock is a ledger. Quantities change only by posting movements; balances are a derived cache.

### stock_movements (T) — document header
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| tenant_id, company_id | uuid FK | |
| movement_type | varchar(20) | CK in (`receipt`, `delivery`, `transfer`, `adjustment`, `return_in`, `return_out`) |
| status | varchar(20) | CK in (`draft`, `posted`, `cancelled`) |
| number | varchar(30) NULL | Set on posting; UQ (company_id, number) where not null |
| movement_date | date | |
| source_warehouse_id | uuid FK NULL | Required for delivery/transfer/return_out |
| destination_warehouse_id | uuid FK NULL | Required for receipt/transfer/return_in |
| purchase_order_id, sales_order_id | uuid FK NULL | Origin document (goods receipt / delivery) |
| reversal_of_id | uuid FK NULL UQ | Compensating movement for a cancellation |
| journal_entry_id | uuid FK NULL | Valuation posting |
| posted_at, posted_by_id | | |

CK: transfer requires both warehouses and they differ; adjustment requires exactly one.
**Goods receipts** are stock movements of type `receipt` linked to a purchase order; this
avoids a second table with the same shape as `stock_movements`.

### stock_movement_lines (T)
`id`, `tenant_id`, `movement_id` FK, `product_id` FK, `quantity NUMERIC(18,4)` CK `> 0`,
`uom_id` FK, `quantity_base NUMERIC(18,4)` (converted to product base unit), `unit_cost NUMERIC(18,4)` CK `>= 0`,
`total_cost NUMERIC(18,2)`, `lot_reference` NULL. Adjustments carry a direction (`in`/`out`) on the line.

### stock_ledger_entries (T) — append-only, created at posting
`id bigint identity`, `tenant_id`, `company_id`, `warehouse_id`, `product_id`, `movement_line_id` FK,
`quantity NUMERIC(18,4)` (signed: + in, − out; never 0), `unit_cost`, `value NUMERIC(18,2)` (signed),
`posted_at`. A transfer produces two entries (out of source, into destination).
Index (tenant_id, product_id, warehouse_id, posted_at).

### stock_balances (T) — cache, rebuildable from the ledger
`tenant_id`, `warehouse_id`, `product_id`, `quantity`, `average_cost NUMERIC(18,4)`, `value NUMERIC(18,2)`, `updated_at`.
**PK (warehouse_id, product_id).** Locked `FOR UPDATE` when posting; CK `quantity >= 0` unless the
company allows negative stock (enforced in service). A management command verifies cache == ledger.

## 6. Sales and purchasing

### sales_orders (T)
`id`, `tenant_id`, `company_id`, `branch_id`, `customer_id` FK contacts, `number` NULL,
`status` CK (`draft`, `confirmed`, `done`, `cancelled`) — a draft order is a quotation,
`order_date`, `valid_until` NULL, `currency_code`, `exchange_rate`, `subtotal`, `discount_total`,
`tax_total`, `total` (all `NUMERIC(18,2)`), `notes`, timestamps.
UQ (company_id, number) where not null.

### sales_order_lines (T)
`id`, `tenant_id`, `order_id` FK, `line_no` smallint, `product_id` FK NULL, `description`,
`quantity` CK `> 0`, `uom_id`, `unit_price` CK `>= 0`, `discount_percent` CK 0–100,
`tax_rate_id` NULL, `line_subtotal`, `line_tax`, `line_total`, `quantity_delivered`, `quantity_invoiced`.
UQ (order_id, line_no).

### purchase_orders / purchase_order_lines (T)
Same shape as sales, with `supplier_id`, `expected_date`, `quantity_received`, `quantity_billed`.

### invoices (T) — customer invoices, credit notes, supplier bills, debit notes

| status | varchar(20) | CK in (`draft`, `posted`, `cancelled`) |
| number | varchar(30) NULL | **UQ (company_id, kind, number)** where not null |
| supplier_reference | varchar(60) NULL | Supplier's own bill number; UQ (company_id, contact_id, supplier_reference) for bills |

### fiscal_periods (T)
`id`, `tenant_id`, `company_id`, `fiscal_year` smallint, `period_no` smallint, `start_date`, `end_date`,

### journals (T)
`id`, `tenant_id`, `company_id`, `code`, `name`, `journal_type` CK (`sales`, `purchase`, `cash`, `bank`,

`mobile_money_provider` NULL CK in (`evc_plus`, `zaad`, `sahal`, `edahab`, `other`), `is_active`.
**UQ (company_id, code).** A cash box, a bank account, and a merchant wallet are each a journal.

### journal_entry_lines (T)
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| tenant_id, entry_id | uuid FK | |
| account_id | uuid FK | Must not be a group account |
| contact_id | uuid FK NULL | Required for receivable/payable accounts |
| branch_id | uuid FK NULL | For branch reporting |
| description | text | |
| debit, credit | numeric(18,2) | Base currency. CK `debit >= 0 AND credit >= 0 AND (debit = 0 OR credit = 0) AND debit + credit > 0` |
| currency_code | char(3) | Transaction currency |
| amount_currency | numeric(18,2) | Signed amount in transaction currency |
| exchange_rate | numeric(20,8) | |

**Balance rule:** for every posted entry `SUM(debit) = SUM(credit)`. Enforced by the posting
service and by a `DEFERRABLE INITIALLY DEFERRED` constraint trigger that checks the entry at
commit. **Immutability:** a trigger rejects `UPDATE`/`DELETE` of posted entries and their lines.
Corrections = a new entry with `reversal_of_id` set.

### payment_allocations (T)
`id`, `tenant_id`, `payment_id` FK, `invoice_id` FK, `amount NUMERIC(18,2)` CK `> 0`, `created_at`.
UQ (payment_id, invoice_id). Service rule (with both rows locked): `SUM(allocations of payment) <= payment.amount`
and `invoice.amount_paid <= invoice.total`. Unallocated remainder = customer credit / supplier advance.

## 8. Control

### document_sequences (T)
`id`, `tenant_id`, `company_id`, `document_type` (e.g. `customer_invoice`), `period_key` (fiscal year, e.g. `2026`),
`prefix` (e.g. `INV-2026-`), `next_number bigint` CK `> 0`, `padding smallint`.
**UQ (company_id, document_type, period_key).** Allocation: `SELECT ... FOR UPDATE` inside the posting
transaction → no duplicates, no gaps.

### audit_logs (T, append-only)
`id bigint identity PK`, `tenant_id` NULL (NULL = platform event), `user_id` NULL, `action`
(`create`, `update`, `delete`, `post`, `cancel`, `reverse`, `login`, `permission_change`, ...),
`object_type`, `object_id`, `changes jsonb`, `ip_address inet`, `user_agent`, `request_id uuid`, `created_at`.
Index (tenant_id, object_type, object_id), (tenant_id, created_at). The application DB role has
`INSERT`/`SELECT` only.

### attachments (T, Phase 4+)
`id`, `tenant_id`, `object_type`, `object_id`, `storage_key`, `filename`, `content_type`, `size_bytes`,
`sha256`, `uploaded_by_id`, `created_at`.

## 9. Key posting flows (what one transaction writes)

| Operation | Rows written atomically |
|---|---|
| Post customer invoice (stockable goods) | invoice → posted + number; stock movement (delivery) + lines + ledger entries + balances; journal entry: Dr Receivable / Cr Revenue / Cr Tax, Dr COGS / Cr Inventory; audit log |
| Post supplier bill | invoice → posted; journal entry: Dr Expense or Stock-in-transit / Dr Tax / Cr Payable |
| Post goods receipt | stock movement + ledger + balances (new average cost); journal entry Dr Inventory / Cr Goods received not invoiced |
| Record customer payment (mobile money) | payment → posted; journal entry Dr Mobile wallet / Cr Receivable; allocations; invoices `amount_paid`; audit log |
| Cancel posted invoice | credit note or reversal entry, reversal stock movement; original marked `cancelled`; nothing deleted |

## 10. Entity overview

```
tenants ─┬─ memberships ─ users
         ├─ roles ─ role_permissions ─ permissions
         └─ companies ─┬─ branches
                       ├─ warehouses ─ stock_balances / stock_ledger_entries
                       ├─ accounts, journals, fiscal_periods, tax_rates, document_sequences
                       ├─ sales_orders ─ sales_order_lines
                       ├─ purchase_orders ─ purchase_order_lines
                       ├─ invoices ─ invoice_lines
                       ├─ stock_movements ─ stock_movement_lines
                       ├─ journal_entries ─ journal_entry_lines

```
